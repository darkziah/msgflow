# Tags: company visibility and nesting implemented

Tags are D1 metadata. Migration 0003 introduced workspace-scoped tags with `visibility` values `company`, `shared`, and `private`, plus nullable `parent_tag_id` for nested tags. Company visibility and nesting are therefore implemented rather than deferred; `shared` remains workspace-wide and `private` remains per-Agent.

A Conversation carries many Tags via the `conversation_tags` join table (conversation_id, tag_id, created_by, created_at); tags are workspace-level, not channel-level, so the same tag applies across Facebook and email conversations. Tagging a conversation is a D1 write + DO relay broadcast (the `conversation-updated` pattern from ADR 0004), not a DO-storage mutation.
